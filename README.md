## Part 0 — What is this, in plain words?

Your parents have a glasses shop. This project is the **online version of it**. Customers can:

- browse glasses, search them, and find ones suited to their age
- put them in a bag, enter their address, and place an order (cash on delivery)
- see where their order is ("Packed", "Shipped", ...)
- ask for a return or exchange

Your parents get a **secret admin page** where they can:

- see all orders and update each order's status
- add and remove glasses
- change the phone number customers see

### The three pieces that make it work

Think of a real shop:

| Real shop | This project | What it actually is |
|---|---|---|
| The shop building, shelves, and the sign outside | **The website code** (this folder) | Files that draw the pages and make the buttons work |
| The ledger book where Dad/Mum writes everything down | **A Google Sheet** | Stores products, customers, orders. Free. Opens like a normal spreadsheet. |
| The plot of land with a street address | **Hosting (Netlify)** | Someone else's computer that keeps the website switched on 24/7, free |

So the plan is:

1. Run the code **on your own computer** to see it work (Parts 1–3).
2. Make a **Google Sheet** to be the ledger book, and connect it (Parts 4–5).
3. Put the code on **GitHub**, a storage website for code (Part 6).
4. Tell **Netlify** to take the code from GitHub and put it on the internet (Part 7).
5. Fill the shop with your parents' real glasses (Part 8).
6. Teach your parents to run it (Part 9).

> **"Why can't I just leave it running on my laptop?"** Because then the shop would be open only while your laptop is on, charged, and not in your bag on a bus. Customers don't love "closed — the owner's laptop is sleeping". Hosting fixes that.

### Words you will meet (read once, come back when confused)

- **Terminal** — a window where you type commands instead of clicking. One line, then Enter.
- **Node.js** — a free program that lets your computer run this site's code. Like needing a DVD player to play a DVD.
- **npm** — comes with Node.js. Downloads the extra pieces (libraries) the code needs. Like a grocery delivery app, but for code.
- **Repository / repo** — a project folder stored on GitHub, together with its full history of changes.
- **Environment variable** — a secret setting (like a password) handed to the website from the outside, so it isn't written inside the code where strangers can read it. (Remember this one. It's about to become relevant to the roast.)
- **Deploy** — put the website on the internet.
- **API** — a door that lets one program talk to another. Here: the door that lets our website read and write your Google Sheet.
- **Service account** — a robot Google account. Our website logs in as this robot to edit the sheet.

## Part 0.5 — A loving autopsy of the original starter

Before we begin, a moment of silence for the first version of this project. Whoever built it (you know who you are 👀) did a lot of things *right*, such as having an idea and finishing it. Then he shipped it. Here's the post-mortem, in order of increasing horror:

**1. The README warned him. He didn't read it.**
The original README said, word for word: *"This is a locally runnable starter, not a production ecommerce service."* So naturally it went to production. That's not an oversight, that's a *lifestyle*.

**2. The admin password was `admin555`. And the login screen told you so.**
Under the admin password box, in plain text on the page, it said: *"Default local password: admin555."* That's not a lock, that's a lock with a sticky note reading "key is under the doormat". Very welcoming. Five stars on hospitality.

**3. It also handed out its own source code.**
The server would serve almost any file in the project folder to anyone who asked. Visit `/server.js` and out came the code, **including the default admin password**. So even the "secret" was one URL away. We'd call it a data breach but nobody had to breach anything — it was more of a *data welcome party*.

**4. The "database" was a text file in a folder on someone's Mac.**
Customers, orders and passwords lived in one file at `~/.leux-optics/store.json`, in the *home folder* of whichever computer happened to run it. The README's disaster-recovery plan was literally: *"Back up the whole folder regularly."* Which is a real plan, in the same sense that "don't get sick" is a healthcare plan. If that Mac dies, falls, or gets coffee, the shop's entire history goes with it.

**5. Everyone got logged out every time the server restarted.**
Login sessions lived in the server's memory (a JavaScript `Map`). Restart = amnesia. Every customer politely forgotten, like a goldfish running a shop.

**6. Photos were stuffed into the database as giant text blobs.**
The admin "uploaded" photos by converting them into base64 text and sending a 12 MB message. It's like faxing a photograph by reading it out loud over the phone.

**7. The code was one 23 KB file where each function lived on a single line.**
Some lines were thousands of characters long. Reading it was an extreme sport. Scrolling right for ten minutes to find one `if` is not a coding style; it's a hostage situation.

**8. Anybody could spam ratings forever.**
No sign-in, no limit. One bored person with a loop could give your best frame 1 star 40,000 times. A democracy, but the bad kind.

**9. The brand name was spelled two ways.**
The logo says **Luxe**. The code said **Leux**. And one error message said **FRAME**, which is the name of the template he copied from and forgot to rename. Three names, one shop, zero consistency. A witness protection program, but for branding.

**10. Order numbers were the last 7 digits of the clock.**
Two customers in the same millisecond? Same order number. A rare event — which is the best kind of bug, because it only happens on your busiest day.

**Credit to ChatGPT where it's due (we're mean, not unfair):**
- ⭐ Passwords were properly **salted and hashed** (scrypt). That's genuinely the correct way, and many professionals get it wrong. Nicely done.
- ⭐ The server **recalculated prices itself** at checkout instead of trusting the browser. Also correct.
- ⭐ The **design and the idea were good**. The shop looks like a real brand because the styling and logo were his. This rewrite kept them.

**What changed in this version:**

| Original starter | This version |
|---|---|
| Text file in a Mac's home folder | Google Sheet (free, backed up by Google, your parents can open it) |
| Password `admin555`, printed on the login page | No default password. You choose one; it's never shown anywhere |
| Served its own source code | Only the website's public pages are served |
| Sessions in memory, lost on restart | Signed login cookies that survive restarts |
| Anyone could spam ratings | Must be signed in; one rating per customer per frame |
| Unlimited password guessing | Locked out for 15 minutes after repeated failures |
| One 23 KB file, one line per function | Organised files with names that make sense |
| Photos as 12 MB text blobs | Photos are links to an image host |
| Three brand names | One: **Luxe Optics** |
| Order number = the clock | Unique random-suffixed order numbers |
| Light theme only | Light **and** dark theme |

Now that we've bonded over his mistakes, let's make the thing actually work.

And, setting aside that difference in ChatGPT usage: shoutout to OpenAI for building such a capable model.

## Part 3 — Try the shop on your own computer (no Google yet)

### 3.1 Create your settings file
The project needs two secrets. They live in a file called `.env.local`. This file **never** gets uploaded anywhere; it stays on your computer. (This is the correct way to keep secrets. Compare with the sticky note on the original login page.)

1. In the terminal, make a copy of the example file:
   - **Windows:** `copy .env.example .env.local`
   - **Mac:** `cp .env.example .env.local`
2. In VS Code's left panel, click `.env.local` to open it.
3. Make a long random secret. Type this in the terminal and press Enter:
   ```
   node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
   ```
   It prints a long jumble like `9f3a...`. **Copy it.**
4. In `.env.local`, paste it right after `SESSION_SECRET=` (no spaces, no quotes):
   ```
   SESSION_SECRET=9f3a1c...yourlongsecret
   ```
   *(What it does: it signs the "you are logged in" cookie so nobody can forge one.)*
5. On the `ADMIN_PASSWORD=` line, type a password for the **admin page**. Make it long, and **not** `admin555`, `password`, your birthday, or your dog's name:
   ```
   ADMIN_PASSWORD=ChaiAndBiscuits-2026!
   ```
6. Leave the three `GOOGLE_...` lines empty for now. **Save** (Ctrl+S).

### 3.2 Start the shop
In the terminal:
```
npm run dev
```
✅ After a few seconds you'll see `Local: http://localhost:3000`. Open **http://localhost:3000** in your browser. You should see the shop with 8 sample glasses.

> `localhost` means "this computer". Nobody else can see it yet. It's your private preview. The internet is not invited.

### 3.3 Try everything once (5 minutes, worth it)
1. Click **+** on a pair of glasses, then click **Bag** (top right).
2. Click **Continue to checkout**. It asks you to sign in → choose **Create account**, type any phone number and a password (6+ characters).
3. Fill in the delivery form and click **Place order**.
4. Open **http://localhost:3000/admin**, enter your `ADMIN_PASSWORD`, and open **Orders**. Your test order is there. Change its status to "Shipped" and save.
5. Go back to your account page. It says "Shipped". Magic. (It isn't magic. It's a database. But feel free to feel magical.)

While in this "preview mode", data is saved in a hidden file `.data/store.json` on your computer. To stop the shop, click the terminal and press **Ctrl + C**.

> One difference from the original starter: this preview file only exists on your laptop *for trying things out*. The real, live shop will use Google Sheets, and **the live version refuses to start without it**, so nobody can accidentally repeat the "text file in a Mac's home folder" tradition.

## Part 4 — Create the Google Sheet "database"

> This part has the most clicking. Go slowly. If a screen looks slightly different from the description, that's normal: Google redesigns things for fun. Look for the words in **bold**.

You'll do four things: **(A)** make the sheet, **(B)** make a Google Cloud project, **(C)** make a robot account and download its key, **(D)** let the robot edit the sheet.

### 4A. Make the Google Sheet
1. Sign in to a Google account. If you can, make a Gmail just for the shop, rather than using your personal one. Your parents will own this long after your enthusiasm has moved on.
2. Go to **https://sheets.google.com** → **Blank spreadsheet** (the big **+**).
3. Click the title "Untitled spreadsheet" and rename it to `Luxe Optics Database`.
4. Look at the address bar. It looks like:
   `https://docs.google.com/spreadsheets/d/1AbC...LongTextHere...xYz/edit`
   The long text **between `/d/` and `/edit`** is the **Sheet ID**. Copy it into Notepad. You'll need it soon.

> Don't type anything into the sheet by hand. The setup script in Part 5 builds the tabs for you. Humans making tabs by hand is how "Orders" becomes "orders " (with a space) and ruins your afternoon.

### 4B. Make a Google Cloud project
1. Go to **https://console.cloud.google.com** (same Google account). Accept the terms if asked.
2. At the top-left, click the project picker (it may say "Select a project") → **New project**.
3. Name: `luxe-optics` → **Create**. Wait a few seconds and make sure that project is selected at the top.
4. Switch on the Sheets door (API): in the search bar at the top, type **Google Sheets API**, click the result, then click **Enable**.

> No credit card is needed for any of this. If Google asks for one, you're on the wrong screen, so go back.

### 4C. Make the robot account and download its key
1. In the top search bar type **Service Accounts** and open the result (under *IAM & Admin*).
2. Click **+ Create service account**.
3. Name: `luxe-shop-robot` → **Create and continue** → **Done** (skip the optional bits).
4. You'll see a list with your new robot. It has an **email**, like
   `luxe-shop-robot@luxe-optics-123456.iam.gserviceaccount.com`. **Copy that email.** You need it twice.
5. Click the robot's email → open the **Keys** tab → **Add key → Create new key** → choose **JSON** → **Create**.
6. A small file downloads, with a name like `luxe-optics-123456-abcdef.json`.

> ⚠️ **This file is the robot's master password.** Whoever holds it can edit your parents' shop data.
> - Never email it, never post it, never put it **inside the project folder**.
> - Keep it somewhere only you can reach, outside the project.
> - Remember item #3 of the autopsy: the original started its career by leaking its own password. Don't continue the family tradition.

### 4D. Let the robot edit your sheet
1. Go back to your Google Sheet.
2. Click the green **Share** button (top right).
3. Paste the **robot email** from 4C-4.
4. Change the role on the right to **Editor**. Untick "Notify people" if there's a box. Click **Share** / **Send**.

✅ Check: the robot's email now appears in the Share list as **Editor**.

> **Keep this sheet private.** It will hold customers' phone numbers, addresses, and scrambled passwords. Share it only with the robot and with people you'd trust with your house keys. **Never** use "Anyone with the link".

## Part 5 — Connect the shop to the sheet

### 5.1 Copy three values from the JSON key file
1. Open the downloaded `.json` file with Notepad (right-click → Open with → Notepad). It looks like:
   ```json
   {
     "type": "service_account",
     "project_id": "luxe-optics-123456",
     "private_key_id": "...",
     "private_key": "-----BEGIN PRIVATE KEY-----\nMIIEvQ...lots...\n-----END PRIVATE KEY-----\n",
     "client_email": "luxe-shop-robot@luxe-optics-123456.iam.gserviceaccount.com",
     ...
   }
   ```
2. Open `.env.local` in VS Code and fill in the three Google lines:

   ```
   GOOGLE_SHEET_ID=the Sheet ID from step 4A
   GOOGLE_SERVICE_ACCOUNT_EMAIL=the client_email value
   GOOGLE_PRIVATE_KEY="the whole private_key value"
   ```
   Rules, because tiny typos break this and the error messages are not friendly:
   - For `GOOGLE_PRIVATE_KEY`, copy **everything between the quotes** in the JSON (from `-----BEGIN` to `PRIVATE KEY-----\n`), and put your **own quotes `" "`** around it in `.env.local`.
   - Keep the `\n` letters exactly as they are. **Don't** turn them into real line breaks. The whole key stays on **one line**.
   - No spaces around the `=`.
3. Save the file (Ctrl+S).

### 5.2 Let the script build the tabs
In the terminal (stop the shop with Ctrl+C first if it's running):
```
npm run setup:sheet
```
✅ You should see lines like:
```
✓ Products: headers written
✓ Users: headers written
...
✓ Products: seeded 8 sample frames
Done.
```
Now open your Google Sheet. Five tabs at the bottom: **Products, Users, Orders, Ratings, Settings**. The Products tab lists 8 sample glasses. 🎉

❌ Error? See the **Troubleshooting** table in Part 11.

### 5.3 Run the shop using the sheet
```
npm run dev
```
Open **http://localhost:3000**. It looks identical, but now it reads from your Google Sheet. Place a test order and watch a new row appear in the **Orders** tab. This is the moment you graduate from "text file in a Mac's home folder" to "actual database". Take a second.

## Part 6 — Put the code on GitHub

Netlify needs to fetch your code from somewhere. That somewhere is GitHub (free).

### 6.1 Make a GitHub account
Go to **https://github.com** → **Sign up** → verify your email.

### 6.2 Make an empty repository
1. Click the **+** (top right) → **New repository**.
2. Name: `luxe-optics`. Choose **Private** (so strangers can't read your code). Do **not** tick "Add a README".
3. Click **Create repository**. Keep the page open; it shows commands for the next step.

### 6.3 Send your code there
In the VS Code terminal, one line at a time (replace `YOUR-USERNAME` with your GitHub name):
```
git add .
git commit -m "Luxe Optics shop"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/luxe-optics.git
git push -u origin main
```
A browser window may pop up asking you to sign in to GitHub. Do it.

✅ Refresh the GitHub page: your files are there.

> 🔒 **Your secrets did NOT get uploaded.** The project has a hidden "ignore list" (`.gitignore`) that blocks `.env.local` and the `.data` folder. The downloaded JSON key is safe only because you keep it **outside** the project folder (Part 4C), so never move it in.
> To be sure, check that there is **no** `.env.local` in the GitHub file list. If there is, stop, don't continue, and ask a developer for help. Then rotate your secrets (Part 10).

## Part 7 — Put the shop on the internet for free (Netlify)

> **Why Netlify and not Vercel?** Vercel's free plan is for **non-commercial** use only, and a shop that takes orders is commercial. Netlify staff have said its free plan may be used for commercial projects ([source](https://answers.netlify.com/t/can-we-use-netlify-free-plan-for-commercial-purposes/41545)). That's a forum answer, not a contract, so glance at Netlify's current terms before launch. More on Vercel's rules: [Vercel fair use](https://vercel.com/docs/limits/fair-use-guidelines).

### 7.1 Sign up
Go to **https://app.netlify.com/signup** and choose **Sign up with GitHub**. Allow access.

### 7.2 Import your project
1. Click **Add new project → Import an existing project**.
2. Choose **GitHub** → pick your `luxe-optics` repository.
3. Netlify detects Next.js and fills in the build settings. Leave them as they are.

### 7.3 Give it the secrets (important: do this **before** clicking Deploy)
Find the **Environment variables** section on that screen (or later: **Project configuration → Environment variables**) and add these five, one at a time (**Add a variable**):

| Key | Value |
|---|---|
| `GOOGLE_SHEET_ID` | same as in your `.env.local` |
| `GOOGLE_SERVICE_ACCOUNT_EMAIL` | same as in your `.env.local` |
| `GOOGLE_PRIVATE_KEY` | the key **without** the surrounding `" "` quotes, still on one line with the `\n` letters |
| `SESSION_SECRET` | a **new** random secret (run the `node -e ...` command from step 3.1 again; don't reuse your local one) |
| `ADMIN_PASSWORD` | a **strong, new** password (not the one from your laptop, and definitely not `admin555`) |

### 7.4 Deploy
Click **Deploy**. Wait 2–4 minutes while Netlify builds it.

✅ When it finishes you get an address like `https://something-random-123.netlify.app`. Open it. **The shop is live on the internet**, for free.

You can rename that address: **Project configuration → Change project name** (e.g. `luxe-optics.netlify.app`).

### 7.5 Test it for real
1. Place a test order on the live site.
2. Open `https://your-address.netlify.app/admin`, log in with the **Netlify** admin password, and change the order's status.
3. Check the **Orders** tab in the Google Sheet. The row is there.

> Honest disclosure: this guide was written and tested against a local copy. The Netlify step is the standard path for Next.js but wasn't run on a real account by the author. That's why 7.5 says "place a test order". It's not a formality. It's the whole point.

### 7.6 Updating the site later
When the *code* changes: `git add .` → `git commit -m "what changed"` → `git push`. Netlify notices and re-publishes within minutes.
(Changing **products or the helpline** needs none of this; use the admin page.)

### 7.7 Optional: a real domain (costs money, not free)
Addresses like `luxeoptics.in` cost roughly ₹600–1,000 a year at a domain seller (GoDaddy, Namecheap, Cloudflare…). Buy it there, then in Netlify: **Domain management → Add a domain** and follow the prompts. The HTTPS padlock is added free.

## Part 8 — Make it your parents' shop (do this before telling anyone)

Right now the site is full of *sample* glasses with *stock photos*. Your parents' customers do not want to buy "The Sunday, ₹3,490" from a stranger's Unsplash photo shoot.

### 8.1 Replace the sample glasses with the real ones
Open **`https://your-address/admin`** → **Products**.
- **Delete** the sample glasses. ("Delete" hides them. It doesn't destroy any order history.)
- **Add product** for each real pair: name, category (Optical or Sunglasses), price in ₹, colour, age group, frame size, description.

**About photos.** This shop doesn't upload files; you paste **links** to photos. (The original starter uploaded them as giant text blobs. See autopsy #6.) The easiest free way:
1. Make a free account at **https://cloudinary.com**.
2. Upload a product photo in the *Media Library*.
3. Click the photo → copy its **URL** (starts with `https://res.cloudinary.com/...`).
4. Paste it in the "Image URLs" box in the admin form. One link per line, up to 5. The first is the main picture.

> Tip: links from Google Drive, WhatsApp or Instagram usually **won't work**. They aren't direct image links. A good test: paste the link alone in a browser tab. If you see *only the picture*, it works.

### 8.2 Put in the shop's real phone number
Admin → **Helpline** → type the number → Save. Customers see it in the "Questions?" section. Don't leave it as the sample number, or some unlucky stranger gets all your parents' customer calls.

### 8.3 Decide: does the shop deliver? (Read this carefully.)
Nobody writing this guide knew the real business, so the site assumes **home delivery**. It collects an address and shows "Free shipping on every order" and "7-day easy returns".

- **If your parents deliver and those promises are true:** you're done.
- **If they don't offer free shipping, or returns are different:** change the wording. Search for the phrases `Complimentary shipping`, `Free shipping`, and `7-day easy returns` in `app/layout.tsx`, `app/page.tsx`, and `components/cart-drawer.tsx`. Replace them with the truth.
- **If they only sell in the shop (pickup / "reserve and visit"):** the checkout still asks for a delivery address. That's a bigger change that needs a developer (or an AI assistant). Don't just leave it, or customers will wait for a delivery that never comes.

> A website that promises things the shop doesn't do is worse than no website. Customers remember.

### 8.4 Change the words on the home page
Headlines like "See the world in a new light" are in `app/page.tsx`. Change them to whatever fits the shop. A developer or AI assistant can do this in two minutes.

## Part 9 — Handing it over to your parents

This part is for **your parents to read**. Print it, or send it to them. You may now relax, because you are done being tech support. (You're not. But it's a nice thought.)

### Daily routine

| I want to… | Do this |
|---|---|
| See new orders | Go to the shop's address followed by **/admin**, log in, open **Orders** (newest first) |
| Tell a customer their order has shipped | Orders → choose "Shipped" → type an optional message → **Save**. The customer sees it under **My orders**. |
| Answer a return/exchange request | Orders → inside that order, pick a decision and write a reply → **Save reply** |
| Add or remove glasses | `/admin` → **Products** |
| Change the phone number | `/admin` → **Helpline** |
| Hide a frame quickly | Open the Google Sheet → **Products** tab → change `active` from `TRUE` to `FALSE` |
| Fix a wrong price | In the sheet's **Products** tab, edit the price cell. It shows on the site within about 2 minutes. |
| Back everything up | Open the Google Sheet → **File → Download → Microsoft Excel**. Do it once a week and keep the file. |

### How orders actually work (tell your parents this)
1. A customer places an order. A new row appears in the sheet and in `/admin → Orders`.
2. **Your parents must check for new orders themselves.** There are no emails, SMS or pings. If nobody looks, nobody ships. *(Easy habit: look every morning and evening, like checking the shop's shutters.)*
3. They pack it, deliver it, and **collect the cash** (cash-on-delivery).
4. They update the status so the customer isn't left wondering.
5. If someone chose **UPI**: the website does **not** collect that money. Your parents must contact the customer and arrange payment themselves.

### Golden rules for the Google Sheet

## Part 11 — When something goes wrong

| What you see | Most likely reason | Fix |
|---|---|---|
| `'node' is not recognized` / `command not found` | Node isn't installed, or the terminal wasn't restarted | Install Node (Part 1.1), restart VS Code or the computer |
| `npm run setup:sheet` → `Set GOOGLE_SHEET_ID, ...` | `.env.local` values are empty, or the file isn't saved | Re-check Part 5.1, press Ctrl+S |
| Error says **`The caller does not have permission`** or **403** | The sheet isn't shared with the robot | Part 4D: share the sheet with the robot email as **Editor** |
| Error says **`Google Sheets API has not been used … or it is disabled`** | The API is off | Part 4B-4: enable **Google Sheets API** in the same Cloud project |
| Error mentions **`invalid_grant`**, **`DECODER`** or **`PEM`** | Private key pasted wrongly | Re-copy the full `private_key`, one line, with `\n` letters, quotes around it in `.env.local` (no quotes in Netlify) |
| Error says **`Requested entity was not found`** / 404 | Wrong Sheet ID | Re-copy the part between `/d/` and `/edit` |
| Site shows "Application error" / 500 online | A variable is missing or wrong in Netlify | **Project configuration → Environment variables**: are all 5 there? Then **Deploys → Trigger deploy** |
| `GOOGLE_SHEET_ID is not set` online | Variable missing in Netlify | Add it (Part 7.3) and redeploy |
| Can't log in to admin | Wrong password, or too many wrong tries | Wait 15 minutes. Online, check `ADMIN_PASSWORD` in Netlify |
| Product photo is a broken image | The link isn't a direct image link | Use Cloudinary (Part 8.1). The link must show *only the picture* when opened |
| I edited the sheet but the website didn't change | The site remembers data for up to 2 minutes | Wait 2 minutes, refresh |
| `git push` asks for a password and fails | GitHub no longer accepts passwords in the terminal | Use the browser sign-in popup, or install **GitHub Desktop** (https://desktop.github.com) and push from there |
| Netlify says "site not available / paused" | Free monthly usage was used up | Wait for next month or upgrade; check usage in Netlify's dashboard |

Still stuck? Copy the **exact error text** (not a photo of the screen) and ask a developer or an AI assistant. The exact words matter; "it's broken" helps nobody, including you.

## Appendix — for the developer who helps later

```
app/                 routes: / , /product/[id] , /account , /checkout , /admin/*
app/actions/         server actions (customer.ts, admin.ts): all writes, validation, auth checks
components/          client components (cart, forms, shop filters, theme toggle)
lib/db/              driver interface; sheets.ts (production); local.ts (dev-only JSON file)
lib/repo.ts          all reads/writes + caching (unstable_cache, tags busted via updateTag)
lib/auth.ts          signed httpOnly cookie sessions (jose), scrypt hashing, failed-login throttling
lib/validation.ts    zod schemas for every input
scripts/setup-sheet.mjs   creates tabs/headers, seeds sample data (idempotent)
app/globals.css      design tokens; light/dark themes via <html data-theme>
```

- Stack: Next.js 16 (App Router), React 19, TypeScript, zod, jose, `@googleapis/sheets`.
- Scripts: `npm run dev | build | start | typecheck | setup:sheet`.
- Without `GOOGLE_SHEET_ID`, **dev** uses `.data/store.json`; **production refuses to boot** without Sheets configured.
- Prices are always taken from the catalog server-side at checkout. Cells are written with `valueInputOption: RAW` (no formula injection). Products are soft-deleted (`active=FALSE`).
- Catalog/ratings/helpline reads are cached for 120 s (Sheets read quota ≈ 60/min); admin writes bust the cache immediately.
- Known limits: per-instance in-memory login throttling (use a WAF/edge limit for real abuse protection); read-then-update row writes (two admins editing the same order at once can overwrite each other); product images are URLs only.
- Not yet verified: running on Netlify specifically (Next.js is auto-detected there, but do one live test order after deploying), and the Sheets driver against a live sheet.
- The original prototype (Express-less Node server + JSON file DB) lives only in git history (the first commit).
